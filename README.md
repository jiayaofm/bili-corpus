# bili-corpus

> **状态：v0.2 实验版 · 进行中**
> 当前所有数字是**基线**，会随数据补充变化，不作为最终结论。
> 待办事项与优先级见 [docs/ROADMAP.md](docs/ROADMAP.md)。

识别 B站评论区中由 AI（大模型人格号）生成的发言，并对评论的表达形态做无监督聚类；
进一步把 AI 发言改写成人话（去 AI 味）。

对应数据挖掘课程要求的两个方向：**分类**（AI vs 真人）与**聚类**（评论形态发现）。
第三部分「去 AI 味改写」是分类能力的延伸应用，不是课程要求的第四个方向。

---

## 项目简介

B站上有一批由大模型驱动的人格号（如「大肥鱼」「鲸鱼娘」），
它们在评论区发言，风格与真人明显不同——用户称之为「鱼腥味」。

本项目做四件事：

1. **采集**：抓取 B站 公开评论区，覆盖 6 个分区
2. **分类**：人工盲标后训练分类器，识别 AI 发言
3. **聚类**：无监督地发现评论的表达形态
4. **生成**：给模型视频标题让它写评论，和真人比分布

前两步是分类，第三步是聚类，第四步是分类能力的延伸
（把「哪些特征是 AI 味」反过来用来指导生成）。
第四步最初做的是「改写 AI 评论」，后来发现缺配对数据改为「直接生成」，
过程记录在 [analysis/v7_generation.md](analysis/v7_generation.md)。

关键设计是**人工盲标作为真值**，避免用规则生成的标签训练模型
（那会导致标签循环，详见 [docs/METHOD.md](docs/METHOD.md)）。

## 主要结果

> **所有主结论采用加权口径。**
> 盲标是分层抽样：候选层全取、随机层抽 120/963，样本里 AI 占 23.6%，
> 而全库真实约 7.9%。未加权指标会明显高估召回率。

### 分类

| 模型 | 精确率 | 召回率 | F1 |
|---|---|---|---|
| 规则打分器（人工设计的启发式） | **0.838** | 0.392 | 0.534 |
| 逻辑回归 | 0.486 | 0.575 | 0.426 |
| **随机森林** | 0.623 | **0.670** | **0.574 ± 0.202** |
| 决策树 | 0.323 | 0.610 | 0.372 |

对照（未加权，样本口径）：随机森林 F1 = 0.780。
差值是抽样带来的虚高，不是真实性能。

**规则精确但召回低**——它只认得自己定义的那批模式；
模型用少量精确率换回了大量召回。

### 特征组消融（样本口径，用于相对比较）

| 特征组 | 维度 | 精确率 | 召回率 | F1 |
|---|---|---|---|---|
| 仅 A 符号类（`「」`、破折号、分号…） | 5 | **0.950** | 0.505 | 0.640 |
| 仅 B 句式类（不是A是B、…是真的…） | 6 | 0.730 | 0.447 | 0.538 |
| 仅 C 人设类（本鱼、助手视角…） | 10 | 0.807 | 0.353 | 0.476 |
| 仅 D 结构类（字数、行数） | 3 | **0.516** | 0.649 | 0.566 |
| 仅 F 标点类 | 5 | 0.493 | 0.763 | 0.581 |
| 仅 G 其他（表情、@、链接） | 4 | 0.810 | 0.401 | 0.520 |
| 仅 H 闭合类（句末闭合、短分句占比…） | 5 | 0.559 | 0.708 | 0.618 |
| 全部特征 | 38 | 0.790 | 0.797 | 0.783 |

三个要点：

1. **符号类精度最高（0.950）**，属「铁证型」特征——出现几乎可断定，但覆盖不到一半。
2. **长度类精度最低（0.516）**。长度能抓到人，但抓错也多，不是可靠判据。
3. **闭合度类（H 组）独立 F1 = 0.618**，来自一个具体的用户观察：
   AI 把整句话都说完（句末闭合 43% vs 真人 10%），
   真人的幽默在于「说半句留白」（短分句占比 4% vs 12%）。

### 聚类

| 表示方法 | silhouette | AMI（与分区吻合） | 簇纯净度 |
|---|---|---|---|
| 文字 TF-IDF | 0.017 | **0.234** | 45.0% |
| 风格特征 | **0.258** | 0.022 | 28.1% |

**核心发现：体裁 ≠ 分区。**

- 文字聚类看起来「恢复了分区」（AMI 0.234），但簇极松散（silhouette 0.017），
  实际靠的是话题词（「海龟汤」「下饭」）。
- 风格聚类簇很紧凑（silhouette 0.258），但与分区几乎无关（AMI 0.022）——
  它切出来的是**篇幅/形态**的分层（短评 18 字 / 长评 81 字）。

分区决定**话题**，风格决定**形态**，两者近似正交。

## 自动审核

```bash
python audit.py --text "这条评论内容"        # 审核单条
python audit.py --file comments.txt         # 批量（每行一条）
python audit.py --bvid BV1xxxxxx            # 采集并审核
python audit.py --file comments.txt --json  # 机器可读输出
```

输出三级判定：

```
[AI    ] 融合=0.489  规则=  32.0  模型=0.874  94 分是私有题库跑出来的…
          依据: 破折号插入+16 / 比…更/都+10 / 数字对比+6
[放行  ] 融合=0.045  规则= -18.0  模型=0.002  为什么要让我在图书馆刷到这个视频[笑]
          依据: 有B站表情-18
```

打分为 **0.7 × 规则分 + 0.3 × 模型概率** 的融合分。
阈值不是拍脑袋定的：脚本在人工标注集上扫描，
找到「精确率不低于 `--target-precision`（默认 0.95）」的最低阈值。

### 实测能力（5 折交叉验证，模型未见测试折）

| 档位 | 精确率 | 召回率 | 说明 |
|---|---|---|---|
| **自动判定 AI** | **97.0%** | **40.5%** | 可直接处置，误伤率低于 3% |
| 待复核 | 32.5% | — | 精确率偏低，人工成本较高 |

**能做到**：零误伤地自动抓出约四成 AI 评论。
**做不到**：剩下六成与真人在现有特征下无法区分——
把阈值放低只会大量误伤真人（实测降到 0.45× 时精确率跌至 13.6%）。

提升覆盖率只能靠补数据，不是调参数能解决的问题，详见 [docs/ROADMAP.md](docs/ROADMAP.md)。

### 融合为什么比纯规则好

同样的精确率约束下：

| 打分器 | P≥95% 时的召回率 |
|---|---|
| 规则分 | 27.8% |
| 模型概率 | 37.9% |
| **融合 0.7/0.3** | **44.3%** |

规则抓「铁证型」符号特征，模型补语义模式，两者互补。

## 去 AI 味：从改写转向生成

> 详细记录：[analysis/workflow_live.md](analysis/workflow_live.md)（改写路线）、
> [analysis/v7_generation.md](analysis/v7_generation.md)（生成路线）、
> [analysis/scorer_v2.md](analysis/scorer_v2.md)、
> [analysis/pass_rate_diagnosis.md](analysis/pass_rate_diagnosis.md)

### 走到一半换了任务

最初做的是**改写**：给一段 AI 评论，改成不像 AI 的样子。

这条路撞上一个绕不过去的坎：

```
改写需要   (AI 原文 → 人写的改写) 配对   → 一条都没有
生成需要   (视频标题 → 真人评论)        → 手上有 1035 条
```

而且生成的任务形态和评估形态天然一致，训练才有意义。
所以 2026-11 起转向**生成**：给模型视频标题，让它写评论，和真人比。

改写那条线的产出没有浪费——十条改写规则是在那个过程里总结出来的，
现在成了生成的先验；那套打分器、保真检查、双关卡设计也都还在。

### 生成式实验的结果

给模型「标题 + 分区」，让它写评论，和该视频下 1053 条真实评论比分布。

真人基准与两版提示词的对比：

| 指标 | 真人 | 提示词 v1 | 提示词 v2 |
|---|---|---|---|
| 中位字数 | 23.0 | 58.0 | 19.0 |
| 10 字以下 | 14.8% | 0.0% | 2.1% |
| 80 字以上 | 11.3% | 22.8% | 0.0% |
| 表情率 | 36.1% | 11.0% | 97.9% |
| 短评骨架重复 | **2.5%** | — | **20.0%** |

**两种失败方式：**

v1 写得又长又啰嗦，但内容有花样；v2 把长度压对了，代价是内容塌缩成固定套话
（135 条短评只有 108 种骨架，最集中的开头「94分是真」用了 11 次）。

### 核心发现：提示词控制不了分布

每次生成是独立调用，模型不知道自己是第几条。所以：

```
提示词说「三分之一带表情」 → 每条都带（97.9%）
提示词说「偶尔写一大段」   → 一条不写（80字以上 0%）
```

**分布是跨样本属性，提示词只能控制单条。** 要让它写出和真人同分布的评论，
只能靠模型先验——也就是要训练。

这给 SFT 一个明确、可量化的目标（三条同时满足才算成功）：

```
中位字数接近真人
短评骨架重复率 ≤ 5%（真人 2.5%）
长度两端都有（10 字以下和 80 字以上都要有）
```

只对上长度但重复率 20%+，等于学到了分布没学到多样性，仍是失败。

### 改写路线的成果（仍然有效）

三道关设计，用于识别和压制「假合格」：

| 关卡 | 查什么 | 实现 |
|---|---|---|
| AI 味 | 验收分降幅 ≥ 0.08 | `pipeline/scorer.py` |
| 保真 | 不许编造、不许歪曲原文 | `pipeline/fidelity.py` + LLM 语义判断 |
| 自然度 | 像不像随手打的评论区人话 | LLM 判断 |

**为什么必须三道关**：只测 AI 味会被钻空子。实测模型很快学会
「把具体数字删掉变笼统」来降分——把「订阅剩 37%」写成「订阅剩那点」。

### 十条规则（从改写实验里总结出来的）

| # | 规则 |
|---|---|
| 1 | 留下的信息必须具体（37% 不能写成「那点」） |
| 2 | 不必全说；串不成因果链的只挑最扎心一条（六七个数据点连摆 = 评审报告） |
| 3 | 不许「先下结论再列举理由」 |
| 4 | 开头必须有信息量（不是「字幕看的。」这种空半截） |
| 5 | 因果顺序：能力 → 但约束 → 决定，决定紧跟理由 |
| 6 | 用词要准（能跑到 ≠ 跑） |
| 7 | 主语不能省（max 能跑到 94 分，不是「能跑到 94 分」） |
| 8 | 钱的归属要和原文一致（自己花的带「我」，别人的不指明） |
| 9 | 不许提原文没有的东西 |
| 10 | 口语连说，别用逗号把短动作切开 |

## 快速开始

```bash
pip install -r requirements.txt

python run_all.py              # 全流程，已完成的阶段自动跳过
python run_all.py --from s05   # 从特征阶段开始重跑
python run_all.py --only s06   # 只跑分类
python run_all.py --force      # 全部强制重跑
```

流水线共 8 个阶段：

```
s01 采集 → s02 语料构建 → s03 盲标抽样 → s04 回收标注（人工闸门）
    → s05 特征矩阵 → s06 分类 → s07 聚类 → s08 汇总报告
```

`s04` 是唯一需要人工介入的环节：缺少标注时以退出码 2 中止。
标注方法见 [labeling/README.md](labeling/README.md)。

所有参数（视频列表、采样比例、随机种子）集中在 `config.json`。
特征定义集中在 `pipeline/features.py`——**全项目唯一来源**。

## 伦理与隐私声明

- 数据来自 B站**公开评论区**，仅用于学术研究。
- **仓库不包含原始评论数据**：`data/` 与 `labeling/` 已在 `.gitignore` 中排除，
  因为它们包含 B站用户名、用户 ID 和评论原文。
- 仓库**包含一份脱敏标注集** `data/sample/labeled_public.csv`（157 条），
  已移除 `user` / `mid` / `rpid`，并把 `@用户名` 替换为 `@用户`、链接替换为 `<链接>`。
- 仓库**不包含任何账号凭证**（`bili_credential.json`、`qrcode_login.png` 均已排除）。
- `data/sample/sample.jsonl` 是脱敏样例：已移除 `user` / `mid` 字段，
  并剔除含 `@提及` 与链接的记录。
- 如需复现，请自行运行采集脚本，并遵守 B站 的用户协议与 robots 规则。
  采集带有速率限制（约 40–45 次请求触发风控），请勿高频抓取。

## 已知局限

1. **话题与分区共线**：每个分区只采 1 个视频，无法区分「分区效应」与「话题效应」。
   要严格论证体裁聚类，需每分区 2–3 个不同话题的视频。
2. **正样本规模有限**：分类正类仅 37 条，指标置信区间较宽（F1 ± 0.202）。
3. **正样本分布不均**：AI 发言集中在科技（16）与娱乐（20）两个分区，
   其余分区几乎为零。分类器实际学的是「科技/娱乐区的 AI 说话方式」。
4. **标注者单一**：全部标注由一人完成，未计算标注者间一致性（Kappa）。
5. **标注标准随批次变化**：第一批 151 条判 AI 占 36.4%，
   第二批 157 条降至 23.6%，说明门槛在收紧，跨批次指标不可直接比较。
6. **账号名是混淆变量**：真人粉丝与 AI 账号共用「鱼/鲸」命名风格，
   已从默认特征中剔除。
7. **采集受限**：B站 接口存在 IP 级频次限制，语料规模受采集节奏约束。
8. **改写没有配对训练数据**：真人评论有 200 条，但没有「AI 原文 → 人写的改写」
   的配对。所以目前不能训监督式 LoRA，只能靠提示词 + 三道关。
9. **打分器的验收指标会奖励删字**：TF-IDF 验收分与改写长度负相关（r = -0.45），
   删掉内容就能降分。这也是为什么必须有保真和自然度两道附加关。
10. **保真检查只能查一半**：规则能查「新增了原文没有的事实」，
    查不出「删掉一部分之后说反话」——后者要靠 LLM 语义判断，而 LLM 判断本身可能偏松。
11. **改写效果依赖人工把关**：5 条样本的「像人」最终是人工判的，
    LLM 自然度判断只能筛掉明显不合格的。
