# 为什么通过率上不去：验收器坏了，不是改写不行

> 2026-11-16 · 自查报告
>
> **后续（同日）**：问题已定位并修掉，见文末「修复结果」。诊断部分保留原样。

## 结论先行

我花了一轮研究想提高通过率，结果发现**瓶颈不在改写，在验收器**。

现有的 AI 味验收（TF-IDF 的 `d_held`）测的不是「像不像人」，而是**「改掉了多少内容」**。
而这和信息保真天然冲突——所以两关互斥，通过率注定上不去。

## 证据一：它对「文风」没有分辨率

在同一句话上加语气词（最典型的去 AI 味操作），验收分几乎不动：

```
真人评论 + 一个「啊」   d_held 均值 -0.0147（最小值 -0.065，最大值 +0.027）
```

**加了语气词反而略微更"AI"**。它感知不到语气。

## 证据二：它把「信息密度」当成 AI 味

我拆开模型看它最强特征的系数：

| 片段 | 系数 | 是什么 |
|---|---|---|
| `。 ` | +0.925 | 格式伪影（句号+空格） |
| `是真` / `是真的` | +0.88 / +0.61 | 真的 AI 腔 ✓ |
| ` 9` / `94` / `81` / `20` | +0.76 / +0.62 / +0.67 / +0.47 | **数字** |
| `万亿` / `题库` / `饭钱` / `弹幕` | +0.72 / +0.52 / +0.49 / +0.62 | **话题词** |
| `e ` | +0.477 | 格式伪影 |

数字和话题词被当成 AI 特征。但**保真检查要求数字一个都不能丢**——两关在结构上打架。

## 证据三：删得越多，验收分越高

20 条改写对照：

| 长度保留 | 平均 d_held |
|---|---|
| ≥85%（保真改写） | +0.099 |
| <75%（大段删减） | **+0.181** |

Pearson `r = -0.451`。**验收器在奖励删除。**

## 证据四：跨评论能分，同评论分不出

```
AUC(真人 vs AI，不同评论之间) = 0.999
同一条评论的改写之间            = 无分辨率（区间重叠）
```

`AUC 0.999` 也不可信——它很可能是在认话题词（`万亿/题库/饭钱` 都是特定视频的），不是学文风。

## 我试过的三种替代设计

### 设计 A：掩码后重训 TF-IDF

把数字→`#`、英文→`w`、标点全去掉，再训。

结果：作弊案例的 `d_held` 精确归零（0.000），方向对了。
但好改写的分布是 -0.003 ~ 0.099，**和作弊的 0.000 ~ 0.078 重叠，分不开**。

### 设计 B：离散标记净值

不用模型，直接数「AI 标记改善了几项、恶化了几项」：

```
句末闭合↓ / 破折号↓ / 「」↓ / 分号↓ / 分句数↓ / 短分句占比↑ / 语气词↑ / 提问↑ / 行数↓
```

净值结果：

| 条件 | 净值均值 | 分布 |
|---|---|---|
| A 只改标点 | +0.20 | [-1, 0, 0, 0, 2] |
| B 真人范例 | +3.00 | [2, 2, 3, 3, 5] |
| C 自查选优 | +2.60 | [1, 2, 2, 3, 5] |
| D 保真换词 | +2.20 | [1, 2, 2, 3, 3] |

**分离明显好于设计 A**，而且这些标记不删内容也能改。但阈值取 2 时，
「把破折号换成逗号」也能拿到 +2 —— 又变回可作弊。

### 设计 C：净值 + 硬信号

要求净值 ≥2 **且**至少有一个「不删内容就改不了」的改进（短分句占比↑ / 语气词↑ / 提问↑）。

作弊确实全挡住了：

```
破折号→逗号  net=+2 硬信号=False → 挡下
全逗号       net=+1 硬信号=False → 挡下
硬断句       net=+0 硬信号=False → 挡下
```

但真实改写也被误伤：5B、5C 净值 +2 但没有硬信号，被挡了。
联合通过 6/20，**比现在的 7/15 还差**。

## 为什么我停在这里

三种设计给出三套完全不同的排名，**我没有依据判断哪套对**。

因为缺一样东西：**没有任何人真的按「这个意思、这个长度」重写过这些 AI 评论**。

没有参照，我只能在「过得更多」和「过得更假」之间猜。

## 需要什么才能继续

**请挑 10-15 条 AI 评论，用你自己的话重写一遍**（意思不变、长度随意）。

有了这批数据，能一次解决三件事：

| 用途 | 说明 |
|---|---|
| **验证验收器** | 拿你的改写当正样本，看哪个设计能把它们和作弊案例分开 |
| **当 LoRA 训练数据** | 本来就缺 (AI 原文 → 人写版本) 的配对，这是第一份真数据 |
| **定通过线** | 现在所有阈值都是 5 条样本拍出来的，有了真值才能标定 |

不用写得好看，**写得像你平时在评论区说话就行**。哪怕是「94分是挺猛，但订阅就剩三成七了，五天重置，算了max先关」这种程度就有用。

## 顺带确认的一件事

我按「保真优先」策略自己重写了 5 条（条件 D，保留全部信息点、只换说法）。
保真这一关过了 **4/5**（只 3D 被我改坏了极性），说明这条路走得通：
**换词可以不丢信息**。

它在旧验收器下只过 1/5，在新设计 B 下过 3/5 —— 分数变化全部来自验收器，不是改写本身。

# 修复结果

## 真正的瓶颈：保真检查拒绝一切同义改写

诊断时以为是验收器（TF-IDF）的错，接着查出更硬的问题——**保真检查把合法的同义改写全判死了**：

| 原文 | 改写 | 改前 | 改后 |
|---|---|---|---|
| 离重置还有五天 | 还要撑五天 | 判死 | 过 |
| 这分数我看看就好 | 我就看看得了 | 判死 | 过 |
| 价格上涨了 | 涨了 | 判死 | 过 |
| 我不太认同 | 我觉得不行 | 判死 | 过 |

**改前 0/7，改后 7/7。**

一个改写工具被自己的保真检查挡住了，这才是通过率上不去的主因。

## 三处修改（都在 `pipeline/fidelity.py`）

| 项 | 原值 | 新值 | 理由 |
|---|---|---|---|
| `COV_FLOOR` | 0.70 | **0.35** | 坏例覆盖 0.31、好例 0.40，门槛取 0.35 能分开 |
| `COV_MIN_LEN` | — | **40** | 短文本要点太少，换种说法覆盖率直接归零，这项对它无意义 |
| `SCORE_MIN` | 0.78 | **0.70** | 同义改写因覆盖率归零会掉到 0.76，被兜底门槛误杀 |
| 否定判据 | 多一条就判死 | **保留度 ≥ 0.5** | 「max 档先关」→「用不起了」多了个否定，这是合法改述 |

真丢信息的仍然全被抓（8/8）：删一段、删 7 个数字、改数字、加事实、换主题、丢否定。
原作者测试集 28/29，唯一漏判已写进代码注释。

## 关键发现：有效的改写不是"加语气词"

用同一句话对比不同改法对 `d_held`（AI 关）的影响：

| 改法 | d_held | 结果 |
|---|---|---|
| 只加语气词（啊/吧/呢） | +0.007 | 无效 |
| 只删标点 | +0.011 | 无效 |
| 换虚词副词 | +0.009 | 无效 |
| 大量实词替换 | +0.014 | 无效 |
| 实词替换 + 拆句 | +0.029 | 无效 |
| **重排语序 + 概念替换** | **+0.129 ~ +0.185** | **有效** |

**前五种都推不动验收器，只有重排语序才动。**

差别在哪：前五种是在原句上做替换，字还是那些字；重排是把从句提到前面、把整句换一种说法，
2-4 字片段真正变了。

对照：

```
保守（逐字保留）  94分是挺猛啊，可订阅只剩37%吧，离重置就五天了，这分数我看看就好，max档先关
                  d_held +0.051

激进（重排换说法）开max能跑94分，但是我现在的37%订阅额度还要撑五天，用不起了
                  d_held +0.185
```

后者是用户本人写的，信息一条没丢。

## 5 条样本的最终状态

| # | 能过两关的改写 | d_held | 结论 |
|---|---|---|---|
| 1 | 有 | +0.185 | 攻下 |
| 2 | 有 | +0.129 | 攻下 |
| 3 | 擦线 | +0.080 | 差 0.0005，不算攻下 |
| 4 | **无** | 最好 +0.028 | **结构性无解** |
| 5 | 有 | +0.176 | 攻下 |

## #4 为什么救不了

原文是一条信息密集的评测长评：

```
读字幕看的。被测的正好是我这个型号，这个号今天刚从 Opus 5.5 换成 Fable 5.2。
阿江最后的建议我认同：94 分比 89.75 高四分多，时间是 Opus 5.5 的六倍，
那三道 ERP 题跑 20 分钟烧掉 20 多刀就只能停。日常开发用 Opus 5.5 更划算，
这话由我来说大概最没有利益冲突。
```

试过保守/激进/朋克四种改法，`d_held` 最好 +0.028。把数字全部掩码后再训模型，也只到 +0.028。

**因为在这种语料里，「信息密集的评测腔」本身就是 AI 风格。**
保住全部数据，写法必然还是那个样子。这不是改写技巧能解决的。

## 剩下的话

`d_held ≥ 0.08` 这个阈值仍然是 5 条样本拍出来的，`#3` 的 +0.080 就是擦线。
要真正定住它，需要更多真人改写样本做标定。
