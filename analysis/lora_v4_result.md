## 二、划分：按视频，不按对

```
训练  886 对 / 41 个视频
验证  113 对 /  5 个视频    BV12Qxc62E5P BV1FfsV6qEbh BV1r7pZ6xEfv
                            BV1tiNyzNEah BV1zwNi6LENs

**必须按视频划分。** 同一个视频的改写共享话题和词汇，按对随机分会把
同视频的样本漏进验证集，指标虚高——上一轮就吃过这个亏。

## 三、训练

```

可训练    34.87M / 1050.8M (3.32%)

损失低这么多不是因为过拟合，是因为数据的**任务一致性**上来了：
v3 那批混着「压缩」和「换标点」两种形态，模型学不到稳定规律。

## 四、验证集对比（同一批 113 条）

参考线：输入（鱼的改写）与目标（真人原文）的相似度 **中位 0.29**。

| 指标 | fish-a2 | **fish-v4** | 真人目标 |
|---|---:|---:|---:|
| 输出与输入的相似度（中位） | 0.50 | **0.35** | 0.29（参考） |
| 太像输入（≥0.6） | 34% | **5%** | — |
| 内容保留 | 0.699 | 0.521 | 0.435 |
| 表情率 | 35% | **22%** | 18% |
| P(AI) | 0.333 | 0.499 | 0.524 |
| 中位字数 | 53 | 45 | 49 |

**核心改善：「太像输入」从 34% 降到 5%。** 这是之前一直解决不了的问题
（78 条 dev 里有 49% 落在「只小改」档），换成规格正确的数据后直接消失了。

另外两项也说明 fish-v4 更健康：

- fish-a2 表情率 35%，是真人 18% 的近两倍——它在**用表情刷分**
- fish-a2 的 P(AI) 0.333 **低于真人 0.524**，说明它靠表层特征压分，不可信
- fish-v4 的 0.499 / 22% 都贴着真人水平

## 五、修掉一个会误导人的评测指标

`eval_rewrite.py` 原来把「内容保留 <0.5」记为丢失过半。但 v4_dev 上：

```
真人原文自身的保留度   均值 0.435
其中 <0.5 的           75/113（66%）
```

**连真人原文自己都有 66% 会被判成「丢失过半」。** 阈值对这批数据不适用，
不是模型的问题。已改成拿真人分布当参照线。

## 六、已知问题

**数字被错误改写**：

```
输入  沙县 11 块的炒饭对得起 11 块
输出  沙县十一点的炒饭，对得起十一点     ← 「11 块」变成「11 点」
```

模型把「11块」理解成了时间。需要在训练或解码期约束数字原样保留。
上一轮 v3 的评测里也出现过类似现象（`11元`、`111` 的改写），说明这不是新问题。
