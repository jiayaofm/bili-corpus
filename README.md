# bili-corpus

> **状态：v0.1 实验版 · 进行中**
> 当前所有数字是**基线**，会随数据补充变化，不作为最终结论。
> 待办事项与优先级见 [docs/ROADMAP.md](docs/ROADMAP.md)。

识别 B站评论区中由 AI（大模型人格号）生成的发言，并对评论的表达形态做无监督聚类。

对应数据挖掘课程要求的两个方向：**分类**（AI vs 真人）与**聚类**（评论形态发现）。

---

## 项目简介

B站上有一批由大模型驱动的人格号（如「大肥鱼」「鲸鱼娘」），
它们在评论区发言，风格与真人明显不同——用户称之为「鱼腥味」。

本项目做三件事：

1. **采集**：抓取 B站 公开评论区，覆盖 6 个分区
2. **分类**：人工盲标后训练分类器，识别 AI 发言
3. **聚类**：无监督地发现评论的表达形态

关键设计是**人工盲标作为真值**，避免用规则生成的标签训练模型
（那会导致标签循环，详见 [docs/METHOD.md](docs/METHOD.md)）。

|---|---|---|
| 娱乐 | 280 | 30.5 字 |

这个差异本身就是聚类实验的一部分。

## 主要结果

> **所有主结论采用加权口径。**
> 盲标是分层抽样：候选层全取、随机层抽 120/963，样本里 AI 占 23.6%，
> 而全库真实约 7.9%。未加权指标会明显高估召回率。

### 分类

| 模型 | 精确率 | 召回率 | F1 |
|---|---|---|---|
| 规则打分器（人工设计的启发式） | **0.838** | 0.392 | 0.534 |
| 逻辑回归 | 0.486 | 0.575 | 0.426 |
| **随机森林** | 0.623 | **0.670** | **0.574 ± 0.202** |
| 决策树 | 0.323 | 0.610 | 0.372 |

对照（未加权，样本口径）：随机森林 F1 = 0.780。
差值是抽样带来的虚高，不是真实性能。

**规则精确但召回低**——它只认得自己定义的那批模式；
模型用少量精确率换回了大量召回。

### 特征组消融（样本口径，用于相对比较）

| 特征组 | 维度 | 精确率 | 召回率 | F1 |
|---|---|---|---|---|
| 仅 A 符号类（`「」`、破折号、分号…） | 5 | **0.950** | 0.505 | 0.640 |
| 仅 B 句式类（不是A是B、…是真的…） | 6 | 0.730 | 0.447 | 0.538 |
| 仅 C 人设类（本鱼、助手视角…） | 10 | 0.807 | 0.353 | 0.476 |
| 仅 D 结构类（字数、行数） | 3 | **0.516** | 0.649 | 0.566 |
| 仅 F 标点类 | 5 | 0.493 | 0.763 | 0.581 |
| 仅 G 其他（表情、@、链接） | 4 | 0.810 | 0.401 | 0.520 |
| 仅 H 闭合类（句末闭合、短分句占比…） | 5 | 0.559 | 0.708 | 0.618 |
| 全部特征 | 38 | 0.790 | 0.797 | 0.783 |

三个要点：

1. **符号类精度最高（0.950）**，属「铁证型」特征——出现几乎可断定，但覆盖不到一半。
2. **长度类精度最低（0.516）**。长度能抓到人，但抓错也多，不是可靠判据。
3. **闭合度类（H 组）独立 F1 = 0.618**，来自一个具体的用户观察：
   AI 把整句话都说完（句末闭合 43% vs 真人 10%），
   真人的幽默在于「说半句留白」（短分句占比 4% vs 12%）。

### 聚类

| 表示方法 | silhouette | AMI（与分区吻合） | 簇纯净度 |
|---|---|---|---|
| 文字 TF-IDF | 0.017 | **0.234** | 45.0% |
| 风格特征 | **0.258** | 0.022 | 28.1% |

**核心发现：体裁 ≠ 分区。**

- 文字聚类看起来「恢复了分区」（AMI 0.234），但簇极松散（silhouette 0.017），
  实际靠的是话题词（「海龟汤」「下饭」）。
- 风格聚类簇很紧凑（silhouette 0.258），但与分区几乎无关（AMI 0.022）——
  它切出来的是**篇幅/形态**的分层（短评 18 字 / 长评 81 字）。

分区决定**话题**，风格决定**形态**，两者近似正交。

## 快速开始

```bash
pip install -r requirements.txt

python run_all.py              # 全流程，已完成的阶段自动跳过
python run_all.py --from s05   # 从特征阶段开始重跑
python run_all.py --only s06   # 只跑分类
python run_all.py --force      # 全部强制重跑
```

流水线共 8 个阶段：

```
s01 采集 → s02 语料构建 → s03 盲标抽样 → s04 回收标注（人工闸门）
    → s05 特征矩阵 → s06 分类 → s07 聚类 → s08 汇总报告
```

`s04` 是唯一需要人工介入的环节：缺少标注时以退出码 2 中止。
标注方法见 [labeling/README.md](labeling/README.md)。

所有参数（视频列表、采样比例、随机种子）集中在 `config.json`。
特征定义集中在 `pipeline/features.py`——**全项目唯一来源**。

## 伦理与隐私声明

- 数据来自 B站**公开评论区**，仅用于学术研究。
- **仓库不包含原始评论数据**：`data/` 与 `labeling/` 已在 `.gitignore` 中排除，
  因为它们包含 B站用户名、用户 ID 和评论原文。
- 仓库**包含一份脱敏标注集** `data/sample/labeled_public.csv`（157 条），
  已移除 `user` / `mid` / `rpid`，并把 `@用户名` 替换为 `@用户`、链接替换为 `<链接>`。
- 仓库**不包含任何账号凭证**（`bili_credential.json`、`qrcode_login.png` 均已排除）。
- `data/sample/sample.jsonl` 是脱敏样例：已移除 `user` / `mid` 字段，
  并剔除含 `@提及` 与链接的记录。
- 如需复现，请自行运行采集脚本，并遵守 B站 的用户协议与 robots 规则。
  采集带有速率限制（约 40–45 次请求触发风控），请勿高频抓取。

## 已知局限

1. **话题与分区共线**：每个分区只采 1 个视频，无法区分「分区效应」与「话题效应」。
   要严格论证体裁聚类，需每分区 2–3 个不同话题的视频。
2. **正样本规模有限**：分类正类仅 37 条，指标置信区间较宽（F1 ± 0.202）。
3. **正样本分布不均**：AI 发言集中在科技（16）与娱乐（20）两个分区，
   其余分区几乎为零。分类器实际学的是「科技/娱乐区的 AI 说话方式」。
4. **标注者单一**：全部标注由一人完成，未计算标注者间一致性（Kappa）。
5. **标注标准随批次变化**：第一批 151 条判 AI 占 36.4%，
   第二批 157 条降至 23.6%，说明门槛在收紧，跨批次指标不可直接比较。
6. **账号名是混淆变量**：真人粉丝与 AI 账号共用「鱼/鲸」命名风格，
   已从默认特征中剔除。
7. **采集受限**：B站 接口存在 IP 级频次限制，语料规模受采集节奏约束。
