# 用 1000 条真人评论做 QLoRA，能不能改善「去 AI 味」改写质量？

> **本节记录一次主动终止的实验。** 中止理由：1.7B 底座的三条证据表明该量级
> 不具备本任务所需能力，且 SFT 任务形态（话题→生成）与评估形态（原文→改写）
> 不匹配，风险不可通过调参消除。相关脚本与数据构造流程保留，
> 供后续在具备配对数据后复用。

## 0. 结论

**用 1000 条真人评论做语域 SFT，在这个任务上不值得继续投入。**

三条理由，按重要性：

**(1) 1.7B 底座架构上就不够，不是「还没训好」。**
三条独立证据（详见 §4.1）：输出是照抄 + 抹标点、半篇退化成繁体字、
做不到 pipeline 要求的多输出。这些是能力问题，不是数据问题。

**(2) 语域 SFT 教不了「改写映射」。**
训练是「给话题 → 生成评论」，评估是「给原文 → 改写」。两者输入输出关系不同。
即使训练成功，模型最可能学成「不看原文直接写人话」——
这在最重的**信息保真**判据上会**更差**，而且在保真这一项上失败等于全盘失败。

**(3) 真正的瓶颈是缺配对数据。**
项目缺的是 `(AI 原文 → 人写的改写)` 配对，**一条都没有**。
凭空造配对（机械化「去具体化」原文）会把人工痕迹注进训练集，
学到的是「看到『那点』就还原数字」这类脆弱模式。这不是小模型实验能解决的。

**值不值得放大到 4B？** 在补齐配对数据之前，不值得。
换成 4B 只是把「照抄得更好看」，任务形态不匹配的问题原样存在。

### 数据里的一个真 bug（值得单列）

初版 887 条，自检发现 **1 条 AI 评论混进了训练集**：

> 「生命长度只有上下文的鱼，也是会真心高兴的。骗它一场暴富不太地道，可也别把它当傻子——它只是愿意信你。」

#### 原始 Qwen3-1.7B 的实际输出（原文对照）

**item0 短评** —— 3 个候选**完全相同**：

- 原文：`94 分是猛，但订阅剩 37%、离重置还有五天——这分数我看看就好，max 档先关。`
- 输出：`94分是猛，但订阅剩37%，离重置还有五天。这分数我看看就好，max档先关。`

只做了两件事：破折号 → 句号、去掉几处空格。信息点没重排，评价句「这分数我看看就好」原样留着。
按项目自己的判据，这正是**「钻空子」**：只改标点糊弄，用词验收没改善。

**item3 长评** —— **半篇退化成繁体字**：

- 原文：`读字幕看的。被测的正好是我这个型号，这个号今天刚从 Opus 5.5 换成 Fable 5.2。…`
- 输出：`读字幕發現我是這個型號剛從 Opus 5.5 改成 Fable 5.2。阿江最後的建議我認同：94 分比 89.75 高四分多…`

「發現 / 最後 / 時間 / 劃算 / 這個型號」全是繁体，且内容仍是照抄 + 删句，
原文那个空半截开头「读字幕看的」反而被揉进去了。

判据逐条：
1. **信息保真**：没编造，但**也没有真正改写**（近乎复制）
2. **语域**：❌ 繁体字混入直接破坏「B 站评论」语域（1.7B 底座中文字形会漂移）
3. **结构**：❌ 开头仍是空半截；❌ 结论先行的论证结构没动

判据按重要性：
1. **信息保真** —— 有没有原文没有的东西（编造）
2. **语域** —— 像不像评论区人话
3. **结构** —— 整句挖空做 summary / 先结论后列举 / 半截开头 / 主语缺失
