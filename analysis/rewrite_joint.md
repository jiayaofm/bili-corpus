# 改写双关卡：AI 味 × 信息保真

> 2026-11-16 · 素材 `state/rewrite_abc.json`（5 条 AI 评论 × 3 种改写条件）

## 为什么要做这张表

之前的实验只测了「去 AI 味」这一个维度，结论是「给真人范例改写效果最好」。
加上保真检查后，这个结论**不成立**——最好的那批改写是靠删信息换来的分数。

现在两关一起看：

- **AI 味**：`scorer.compare()` 的 `verdict == "ok"`（不是 `gaming`，也不是 `no-gain`）
- **保真**：`fidelity.check()` 的 `ok == True`

|---|---|---|---|
| 1 | PASS | PASS | PASS |
| 2 | fail（AI 味没降） | fail（丢信息） | fail（丢信息） |
| 3 | fail（AI 味没降） | PASS | PASS |

**7/15 同时过关。**

| 维度 | 结果 |
|---|---|
| A 只给规则 | 1/5（保真没问题，但只是把标点抹平了） |
| B 真人范例 | 3/5 |

| 按文本 | #1 3/3、#3 2/3、#5 2/3、**#2 0/3、#4 0/3** |

## 关键发现：两条路都堵死在长文本上

```
A  保真，但不人味   → 只动标点，被判定为钻空子
B/C 人味，但丢信息  → 大段删减，被判定为不保真
```

失败的 #2 和 #4 有共同特征——**信息密集**：

```
#4 原文  94 分比 89.75 高四分多，时间是 Opus 5.5 的六倍，
         三道 ERP 题跑 20 分钟烧掉 20 多刀就只能停。
#4 B     94分挺猛 可订阅只剩37%…           ← 上面整段数据被删
```

**AI 味和长度/信息密度正相关**：一条信息密集的 AI 评论，最省事的去味方式就是删掉一半内容。
一旦不许删，就现出原形——改写能力不够。

## 因此下一步的约束变了

之前 workflow 的目标是「找到一个 ok 的改写」。现在必须加一条：

```
改写 = 换表达，不是删内容
     = 原文每个信息点都保留，只改说法
```

对 #4 的正确改写应该像这样（全部信息保住，只换口气）：

```
原文  94 分比 89.75 高四分多，时间是 Opus 5.5 的六倍，三道 ERP 题跑 20 分钟烧掉 20 多刀就只能停。
改写  94分是比89.75高四分多吧，可时间六倍啊，三道ERP题跑二十分钟就烧二十多刀，只能停
```

这种改写 A 档做不到（它只会删），B/C 档也没做到（它们选择了删）。需要把
「信息点清单」直接写进生成指令，并让保真检查在**每一轮都跑**，而不是只在最后验收。

## 对既有结论的修正

| 之前的说法 | 修正 |
|---|---|
| 「真人范例改写让 AI 味降到 -2.0，几乎贴到真人水平」 | 说的是**分数**。其中 #2B/#2C/#4B/#4C 是靠删信息换来的，加上保真后不算数 |
| 「只给规则能降 68%」 | 分数确实降了，但 4/5 被判定为钻空子——它只抹平了表面特征 |
| 「few-shot 是上游，LoRA 是下游」 | 仍然成立，但 few-shot 的产物必须先过保真才能当训练数据 |

## 现在的能力边界

| 能力 | 状态 |
|---|---|
| 判断改写是否更像人 | ✅ 有，且能识别钻空子 |
| 判断改写是否保真 | ✅ 有，29 条反例全抓，5 类盲区已写明 |
| 生成合格改写 | ⚠️ 5 条里 3 条能做到，2 条不能 |
| 真实生成器 | ❌ 还没接（workflow 目前用占位生成器验证流程） |

## 下一步

1. 给 workflow 加「保真优先」模式：生成指令里直接给信息点清单，禁止删除
2. 接一个真实生成器，先跑 #2 和 #4 这两条硬骨头，看能不能攻下来
3. 攻不下来就如实记录——这也是结论：**信息密集的 AI 评论，纯改写手段可能去不干净 AI 味**
