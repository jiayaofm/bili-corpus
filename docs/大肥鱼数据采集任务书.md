## 一、要做什么

今天去 B 站逛一圈，产出**两样东西**：

| # | 任务 | 说明 |
|---|---|---|
| **任务一** | 每条视频写一份概要 + 3~5 条你自己的新评论 | 覆盖话题，展示你会怎么评论一条视频 |
| **任务二** | 把这条视频的真人热评，**逐条改写成你自己的口气** | 内容对齐的对照，训练主要靠这个 |

两样产出都指向同一件事：我们要训一个模型，**把「你写的评论」改成「真人网友写的评论」**。

所以：

- **你的评论是 x（要被改掉的东西）**，带腔调越足越好
- **真人评论是 y（要变成的样子）**，越原始越好
- 任务二让 x 和 y 说同一件事，模型才能学到「怎么改」而不是「随便写一条」

**这不是发帖任务，全程不发任何评论。**

两条关键要求：

1. **保持你自己的口气，不要刻意装成普通网友。** 你的写法本身就是数据，改了反而没用。
   我们就是要「去掉你这个腔调」，所以腔调越足，数据越有用。
2. **写新评论（任务一）时，不要参考真人热评。** 顺序在第四节卡死了，别提前看。

## 四、每条视频怎么做

**严格按这个顺序。第 3 步和第 4 步的顺序不能颠倒。**

### 第 1 步：扒素材（不看热评）

```bash
node bili.mjs debrief <BV> --no-comments [--no-frames]
```

**`--no-frames` 什么时候加**：

| 情况 | 命令 |
|---|---|
| **有官方字幕** | `debrief <BV> --no-comments --no-frames` |
| **没有字幕** | `debrief <BV> --no-comments`（需要抽帧，下载视频较慢） |
| 有字幕但内容靠画面（手工、绘画、游戏画面） | 也可以抽帧，自己判断 |

**有字幕就不抽帧**——字幕已经是最准的那一路，抽帧只是给没字幕的兜底。

### 第 2 步：写概要

**80~150 字，只写事实，不评价。**

写清楚：这条视频讲了什么、关键细节有哪些、结论是什么。

> 好的概要：从沈阳一份十块钱的盒饭开始，摊子开了三十年，铝饭盒里装炖刀鱼和几样家常菜。接着换到上海陆家嘴，一份牛脸颊肉拌饭人均一百五，再往上是最贵的那份——黑金鲍、澳洲鲍，老卤酒炖出来。
>
> 不好的概要：这期视频非常有意思，博主通过对比展现了消费差异，令人深思。

### 第 3 步：写 3~5 条你自己的评论

**按你自己的人设写，别模仿弹幕和热评。**

同一个视频写几条，要求是**互相之间不能像**：

- 长度要错落（有的十个字以内，有的三四十字）
- 入口要不一样（有人从数字进，有人从画面进，有人从吐槽进）
- 不要每条都以同一个词开头

**但不要为了「多样化」去刻意分配表情和立场。** 跟着视频内容走就行：
这条适合吐槽就吐槽，适合夸就夸。自然变化，不是设计出来的变化。

### 第 4 步：写完自己的评论之后，再拉真实热评

```bash
node bili.mjs comments <BV> --ps 20 --sort hot --json
```

**必须在你写完自己的评论之后做。** 这一步拿到的是普通观众的真实评论，当「人味侧样本」用。

### 第 5 步：任务二 —— 把真人热评逐条改写成你自己的口气

拿刚拉到的真人热评，**取前 20 条，逐条改写成你自己的口气**。

这一步是整个任务里最重要的。规则很硬：

**要改的：**
- 说法、语气、句式、节奏 —— 换成你自己会怎么说
- 结构 —— 真人爱把两件事揉在一句里，你可以改成两句

**不许改的：**
- **原话说的那件事**。它吐槽什么、夸什么、怀疑什么，改写后必须还是这件
- **原话里的具体信息**：数字、价格、人名、时间、对比对象、地点，一个都不许丢
- **立场**。它觉得不好，你不能改成觉得好

**不许做的：**
- 不许加原话里没有的事实
- 不许把原话改得更长（**长度控制在原文的 50%~130%**）
- 不许只换几个词充数——那不是改写，是复读

举例：

```
原文  有点没活硬整盒饭概念了，后面100与1000与盒饭的关系是？
改写  后面那两个也算盒饭吗，纯粹是拿盒饭当标题

原文  这期视频除了第1个是正经盒饭，后面两个跟盒饭有什么关系？
改写  除了第一个，后面两个跟盒饭没关系吧

原文  后面全在讲车，最后那个一千块的我看着像广告
改写  后面全在讲车，一千块那个像广告
```

**改写完之后自查一遍**：拿原文和改写并排看，问自己「原话说的信息，改写里还都在吗」。
丢了信息的**重写**，不许留着。

## 五、输出格式

每行一个视频，UTF-8，JSONL（不要包成数组）。

```json
{
  "bvid": "BV1rTWq6iEdy",
  "title": "中国最贵vs最便宜！一碗盒饭，价格差100倍，有多大区别？",
  "partition": "美食",
  "up": "Meetfood觅食",
  "duration": "16:45",
  "subs_lines": 467,
  "summary": "80~150 字的概要，只写事实",
  "comments": ["任务一：你自己写的新评论", "第二条", "第三条"],
  "real_comments": ["真人评论原文，原样保留", "不要改写不要润色，错别字也留着"],
  "rewrites": [
    {"origin": "真人评论原文", "rewrite": "你改写成自己口气的版本"},
    {"origin": "另一条原文", "rewrite": "对应的改法"}
  ],
  "sources": ["字幕", "弹幕热区"],
  "notes": "可选：这条视频有什么特殊情况"
}
```

字段说明：

| 字段 | 要求 |
|---|---|
| `bvid` / `title` / `up` / `duration` | 原样填，别改 |
| **`partition`** | **填你搜索时用的那个关键词**（搜「美食」进来的就填「美食」）。接口里的 `tname` 是空的没关系，不用它 |
| **`subs_lines`** | 字幕行数，**没有字幕填 0**。这个字段用来区分「有字幕的」和「靠抽帧看懂的」 |
| `summary` | 80~150 字，只写事实 |
| `comments` | **任务一：你的新评论，3~5 条** |
| `real_comments` | 真实热评原文，**原样复制**，别改字，别挑好看的 |
| **`rewrites`** | **任务二：前 20 条真人热评的逐条改写**，`origin` 必须和 `real_comments` 里的某一条**逐字一致** |
| `sources` | 你实际看了哪几路，如 `["字幕","弹幕热区","抽帧"]` |
| `notes` | 跳过的、写偏的、有争议的，写清楚 |

**`rewrites` 的三条硬规定：**

1. `origin` 必须**逐字复制** `real_comments` 里的一条，不许改写、不许截断加省略号
2. 一条 `real_comments` 只能对应一条 `rewrite`，**不许一对多**
3. `rewrites` 条数 = min(20, `real_comments` 条数)

**跳过的视频也要留一行**：

```json
{"bvid": "BV...", "title": "...", "partition": "...", "skipped": true, "notes": "没有字幕，弹幕也没对上，看不懂讲了什么"}
```

## 八、为什么这么做（理解意图，别只机械执行）

我们在做一个「去 AI 味」的改写模型，但这里的「AI 味」特指**你的腔调**——不是「不仅…更是…」那种一眼假的 AI 腔，而是你自己那套稳定的句式习惯。

```
x（AI 侧）   你写的评论        ← 带着你的腔调，要被改掉
y（人味侧）  真人评论          ← 要变成的样子
```

**任务二才是训练的主力**，因为只有它保证 x 和 y 在说同一件事。

举个反例：如果只有任务一，配对会是这样——

```
x  你：海参那段弹幕全在刷国足
y  真人：这期除了第一个是正经盒饭，后面两个跟盒饭啥关系
```

说的不是同一件事。模型会学成「忽略原文，随便写条人话」，**你看视频看到的那个具体发现就丢了**。

任务二把这个问题解决了：原文和改写都在这件事上，模型只能学「怎么说变了、说什么没变」。

所以：

- **你的口气越足，数据越有用。** 别收敛，别装普通网友
- **真人的评论越原始越好。** 错别字、脏话、跑题、只有两个字——全都留着
- **概要必须准确。** 它会是训练时的输入上下文，写错了整个样本就废了
- **改写真评时，宁短勿丢。** 宁可少说一句，也不能把原话的信息吃掉
- **不要刻意制造多样性。** 你自己的腔调是固定的，那是特征不是缺陷；
  但别让 200 条都从同一个句式开头，那是模板，会被当成噪声学进去

如果某条视频你实在没话讲，跳过它。**跳过比硬写强**——硬写的评论会变成噪声。
