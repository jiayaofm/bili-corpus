# 摘要条件生成：数据扩 10 倍后的四组对照

> 2026-11-19 这一轮。核心问题：**给模型看视频摘要，它能不能写出咬住内容的评论？**
>
> 结论先说：**风格对上了，内容只对了一半，还踩出一个新坑（@ 污染）。**

## 一、这次改了什么

| | 上一版（gen2） | 这一版（gen3/gen4） |
|---|---|---|
| 输入 | 只有标题 | 标题 + 视频摘要 |
| 训练样本 | 2,069 | 6,927 |
| 语料覆盖 | 1,053 条（4.2%） | 9,167 条（36.3%） |
| 摘要来源 | — | 官方字幕 + 简介 + 标签 |

**摘要不是模型编的**，是从视频里抽出来的真材料：

```
✓ 简介      up 自己写的
✓ 官方字幕  几百行台词（7 个视频共 1195 行）
✓ 标签      up 自己打的分类
✗ 热评      刻意不取 —— 那是要预测的标签，取了就是泄题
```

`bili.mjs video` 这条命令本身不含热评，所以泄题在源头被结构性排除。

## 二、四组对照

同一批视频、同样 20 条/视频、同样温度 1.25：

| 组 | 中位字数 | 均值 | <10字 | >80字 | 表情率 | 骨架重复 | 分类器判 AI |
|---|---:|---:|---:|---:|---:|---:|---:|
| **真人** | **23.0** | 41.8 | 14.8% | 11.3% | 36.1% | 3.2% | — |
| 底座 + 摘要 | 145.0 | 148.2 | 0.0% | 100.0% | 5.7% | 70.0% | 0.480 |
| gen3 + 摘要（未清洗） | 25.4 | 30.4 | 12.9% | 4.3% | 52.1% | 0.0% | 0.356 |
| **gen4 + 摘要（去 @）** | **21.0** | 29.2 | **14.3%** | 5.0% | 60.7% | 4.3% | **0.345** |
| gen2 + 标题 | 22.0 | — | 8.6% | 4.3% | 72.9% | — | — |

### 三条能站住的结论

**① 底座模型拿同样的摘要，写的是小作文。**

中位 145 字，**100% 超过 80 字**，表情 5.7% —— 真人里超过 80 字的只有 11.3%。
这是最典型的「AI 写作腔」：完整、工整、有转折、没情绪。

**② LoRA 的价值就是把语域掰回来。**

gen3 中位 25.4 字（真人 23.0），>80 字降到 4.3%（底座 100%）。
**骨架重复 0%**（底座 70% —— 它反复用同一个开头模板）。

**③ 加摘要之后，风格指标进一步向真人靠。**

| 指标 | gen2（标题） | gen3（摘要） | 真人 |
|---|---:|---:|---:|
| 表情率 | 72.9% | **52.1%** | 36.1% |
| <10 字 | 8.6% | **12.9%** | 14.8% |

表情从「满屏 emoji」降到 52%，短评占比从 8.6% 升到 12.9% —— 都朝真人方向走。
**这是我们自己的分类器给的分：底座 0.480 → gen3 0.356**，越接近 0 越像人。

## 三、没做到的部分（必须说清楚）

### 内容只对了一半

人工读 gen3 的 140 条，大致三类各占三分之一：

```
咬住内容的 ✓
  因为中国在古代主要的食物储备都是大米，然后通过长期的饥荒导致很多人一辈子吃不饱
  这条讲得好，下饭这事背后是中国人的历史烙印，不是夸菜有多好吃

空的 ✗
  太神了[笑哭]，我方块蛋糕都做不下去了
  up真的会做美食啊！！！[打call][点赞][给心心]

垃圾 ✗
  点赞+关注+评论@阿飞吃鸡[星星眼]
```

**「复现了摘要里的具体数字」gen3 是 7.9%，gen4 是 7.1%** ——
基本没变，也就是说**去 @ 只解决了格式问题，没解决内容问题**。

（我另外写过一个「与摘要共享内容词」的指标，结果是 0.0% —— 那个正则太粗糙，
误判率高，**不采信这个数**。）

**结论要说清楚**：这一轮让「像不像人」这件事大幅改善（长度、表情、@ 率、P(AI) 全面向真人靠），
但「说的内容对不对」只从 0 改善到 7~8%。**风格问题解决了，内容问题没解决。**

1.7B + 6.9k 样本的组合，能学会「怎么说」，还学不会「说什么」。
下一步要动内容，得从这两头想办法：
- 模型那头：换更大的底座（4B/8B）
- 数据那头：现在每视频只有 1 条摘要，模型见不到「同一件事的不同说法」

### 新出现的坑：25% 的评论以 @ 开头

```
gen3·摘要    @开头 25.0%   ← 崩了
gen2         @开头  4.3%
底座         @开头  0.0%
真人顶层评论  @开头  0.0%
```

**根因查到了：扩采把训练数据污染了。**

| 数据集 | 样本 | 目标里的 @ 开头 |
|---|---:|---:|
| gen3 训练集 | 6,977 | **11.35%** |
| gen2 训练集 | 2,069 | 1.6% |

老数据集是人工清洗过的；扩采进来的 5,790 条顶层评论里，
**大量以「@某人」开头** —— 那是 B站 评论区里手动 @ 别人的回复，不是独立顶层评论。
模型把这个格式学去了。

**修复**：`build_dataset.py` 加了 `--drop-at`，剥掉行首的 @ 序列，
剥完不足 6 字的直接丢弃。

```
ds_v3  (无 --drop-at)   6977 条  @开头 11.35%
ds_v3b (加了 --drop-at)  6927 条  @开头  0.00%
                        （剥掉 873 条，丢弃 128 条）
```

**重训为 gen4 后，@ 率归零，其他指标没有变差：**

| | @ 开头 | 中位字数 | <10字 | 表情率 | P(AI) |
|---|---:|---:|---:|---:|---:|
| gen3（未清洗） | **25.0%** | 25.4 | 12.9% | 52.1% | 0.3564 |
| gen4（去 @ 后） | **0.0%** | 21.0 | 14.3% | 60.7% | **0.3445** |
| 真人 | 0.0% | 23.0 | 14.8% | 36.1% | — |

**修复不只是把 @ 去掉，整体还更好了**：P(AI) 从 0.3564 降到 0.3445，
`<10 字` 占比 14.3% —— 和真人的 14.8% 几乎重合。

唯一变差的是表情率：52.1% → 60.7%（真人 36.1%）。
推测是少了 @ 前缀这个长度来源后，模型用表情补足「短」的观感。**这条没验证，只是推测。**

## 四、这一轮暴露的方法论问题

**扩数据不等于变好。** 从 1,053 到 9,167 条，样本多了 8.7 倍，
但带进来 11.35% 的 @ 污染 —— 这是个**负收益**，必须靠清洗抵消掉。

这件事对课程报告有直接价值：

> 数据量的增长和质量的增长是两个独立的轴。
> 我们扩采 8.7 倍，同时引入了一个指标从 1.6% 恶化到 11.35% 的污染，
> 只能靠人工定规则（剥 @ 前缀）抵消回去。
> **这正说明「数据清洗」不是可选项。**

## 五、追加对照：本地 Qwen3-8B（Ollama）

原来的疑问是：**「写不出像人的评论」到底是模型太小，还是没训过？**

拿本机 Ollama 上的 `qwen3:8b-tool`（Q4 量化，5.2 GB）跑同一个「摘要 → 评论」任务，
提示词、温度、条数全部对齐，**不训练，只提问**。

| | 中位字数 | >80字 | 表情率 | **骨架重复** | P(AI) | 事实复现 |
|---|---:|---:|---:|---:|---:|---:|
| **真人** | 23.0 | 11.3% | 36.1% | 3.2% | — | — |
| 1.7B 底座 | 145 | 100% | 5.7% | **70.0%** | 0.4802 | — |
| **8B（Q4）** | 46.0 | 0% | **0%** | **65.7%** | 0.4567 | 9.3% |
| **gen4 LoRA（1.7B）** | 21.0 | 5.0% | 60.7% | **4.3%** | **0.3445** | 7.1% |

### 结论：规模解决了「长度」，没解决「AI 味」

**规模确实有用的一半**：

```
1.7B 底座  中位 145 字，100% 超 80 字   ← 写小作文
8B         中位  46 字，0% 超 80 字      ← 不写小作文了
真人       中位  23 字
```

参数大 4.7 倍，直接把「写小作文」这个问题解决掉了 2/3。
**说明「AI 爱写长」这件事，确实有规模效应。**

**但规模完全没解决的另一半 —— 模板化**：

```
8B 骨架重复   65.7%   最频前缀「这视频真是把」×25（140 条里 25 条同一个开头）
1.7B 底座     70.0%   最频前缀「这个视频真的」×24
gen4 LoRA      4.3%   最频前缀「哈哈哈哈哈哈」×4
真人           3.2%
```

8B 和 1.7B 底座的模板化程度几乎一样（65.7% vs 70.0%）。
**这说明「模板化」不是参数不够，是没被教过。**

8B 在「下饭」那条视频上生成的 20 条，实际长这样：

```
"下饭"不只是评价，更是中国人用味觉丈量生活的刻度。
"下饭"不仅是味觉的满足，更是中国人对生活节奏的妥协——…
"下饭"不仅是味觉的满足，更是中国人对食物与生活节奏之间微妙平衡的智慧体现。
"下饭"不仅是味觉的满足，更是文化与生存智慧的沉淀…
"下饭"不只是评价，更是饮食文化的缩影…
```

**同一个句式套 20 遍。** 这是最标准的「AI 味」。

我们自己的分类器也给了一致的判断：
**8B 的 P(AI)=0.4567，几乎和 1.7B 底座（0.4802）一个水平；LoRA 是 0.3445。**

### 内容层面：8B 略好，但没有质变

```
8B 事实复现   9.3%
LoRA 事实复现  7.1%
```

大 4.7 倍的模型，在「引用摘要里具体数字」这件事上只比 1.7B+LoRA 高 2 个百分点。
**说明内容空心不是「想不出来」，是「没被要求」。**

### 这一跑给了什么

1. **换大模型不值得。** 8B 在关键指标（模板化、P(AI)）上打不过一个 1.7B + 6.9k 样本的 LoRA。
2. **LoRA 路线的价值被量化了。** 模板重复 65.7% → 4.3%，是 15 倍的差距。
3. **内容问题是独立问题。** 参数从 1.7B 到 8B，事实复现 7.1% → 9.3%，几乎没动。
   要解决它得改训练数据的组织方式（比如每视频多个摘要版本），不是换模型。

### 一个必须声明的局限

**这个 8B 是 Q4 量化的 GGUF**，不是原始精度。
量化会损伤能力，所以严格说这是「8B-Q4」而不是「8B」。
但差距这么悬殊（模板化 65.7% vs 4.3%），量化不可能解释掉。
何况要跑全精度 8B，8 GB 显存根本装不下。

## 六、可复现

```powershell
# 1. 抓素材（字幕 + 简介 + 标签）
python tools\fetch_materials.py

# 2. 写摘要（模型读素材后写，产物 data/summaries/<BV>.json）
#    —— 这一步由 agent 完成，不是脚本

# 3. 造数据集（--drop-at 是这次新加的，必带）
python tools\build_dataset.py --with-summary --strip-reply-prefix --drop-at --out data\ds_v3b

# 4. 训练
python tools\train_lora.py --data <sft_train.jsonl> --out <adapter> `
    --max-len 320 --bs 2 --grad-accum 8 --epochs 3 --vram-frac 0.7

# 5. 评估（--prompt summary 是这次新加的）
python tools\eval_generation.py --tag gen4 --prompt summary --adapter <adapter> `
    --n 20 --temperature 1.25
```

## 七、显存参数的两个坑

**① `--max-len` 别照抄 512。**
实测样本 token 长度 p50=171 / p99=272 / 最大 310。
按 512 给，等于白占近一倍显存，**第一次训练就是这么 OOM 的**。
改成 320，零截断。

**② `--vram-frac` 0.5 太保守。**
8 GB 卡上 0.5 = 3.98 GB 上限，跑 bs=2 会 OOM。
改 0.7（≈5.6 GB），峰值实际只用到 3.81 GB。
