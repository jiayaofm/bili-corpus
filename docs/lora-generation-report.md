# 本地 QLoRA 生成实验：让 1.7B 学会写 B 站评论

> 任务形态：**生成**（给视频标题 → 写一条评论），不是改写。
> 训练与评估形态一致，这是相对上一轮改写实验的关键修正。

实验时间：2026-11-17
产物：`D:\dsh-ai\lora\out\qwen3-1.7b-gen`（LoRA adapter 25 MB，3 epoch 跑满）

---

## §0 结论

**结论：训练确实学到了东西，长度分布大幅改善；但表情率严重超标，且模型没有读话题。
所以「学到了一半」——学的是**语域**（怎么说），没学会**内容**（说什么）。**

三条判据逐条交代：

| 判据 | 结果 | 判定 |
|---|---|---|
| ① 长度分布 | 中位 132 → **29**（真人 23），均值 142.5 → **37.7**（真人 41.8） | ✅ **大幅改善** |
| ② 骨架重复率 | 25.0% → **0.0%**（真人 3.2%） | ✅ **改善，甚至比真人更分散** |
| ③ loss 对照 | 11.42 → **4.57**（−6.85） | ✅ **确实学到了** |
| 额外：表情率 | 14.3% → **78.6%**（真人 36.1%） | ❌ **严重超标** |
| 额外：<10 字占比 | 0% → 3.6%（真人 14.8%） | ❌ **一句话短评能力没学到** |
| 额外：话题相关性 | 读样本可判：**基本不看话题** | ❌ **内容空心** |

**一句话**：LoRA 把「写多长、长什么样」教会了，没把「针对这个视频说什么」教会。
前者是分布学习，后者需要语义理解——1.7B 的能力边界在这里。

**数值证据**（loss 对照，同一 holdout、只算 assistant 段）：

```
底座   loss 11.4202  perplexity 91,147   p_target 0.0011%
LoRA   loss  4.5727  perplexity     96.8 p_target 1.03%
```

底座给真实评论的平均概率几乎是 0（1.1e-05），LoRA 提到 1%。**不是「任务熵高导致 loss 压不动」——
底座和 LoRA 之间差了 6.85 个点，这个差距证明 LoRA 学到了东西。**

## §1 任务定义：为什么是生成不是改写

上一轮做的是「AI 原文 → 人写的改写」。这条路走不通：

1. **配对数据一条都没有**。项目里没有 `(AI 原文 → 人写的改写)` 成对样本，
   靠机械「去具体化」造配对会把人工痕迹注进训练集。
2. **训练形态和评估形态不一致**：SFT 是「给话题→生成」，评估是「给原文→改写」。
   模型最可能学成「不看原文直接写人话」，在保真判据上更差。

改成生成后两个问题同时消失：

```
输入：视频标题 + 分区
输出：一条评论
评估：和该视频下真实评论比分布
```

## §3 训练

```powershell
train_lora.py --bs 2 --grad-accum 8 --epochs 3 --max-len 512 \
              --vram-frac 0.5 --min-free-gb 4.0
```

| 项 | 值 |
|---|---|
| 底座 | Qwen/Qwen3-1.7B |
| 量化 | 4bit nf4 + double quant，compute bf16 |
| LoRA | r=16, α=32, dropout=0.05, q/k/v/o_proj |
| 可训练参数 | 6.42M / 1022.4M（0.63%） |
| 步数 | **390**（130×3 epoch），跑满 |
| train_loss | 4.277（overall avg） |
| **耗时** | **3018 秒 = 50.3 分钟** |
| **峰值显存** | **3533.6 MiB**（reserved 3924），未超 4GB |
| 存盘 | `save_strategy=epoch`（checkpoint-260 / checkpoint-390 都在） |

### 一个值得记录的工程观察：瓶颈不在显存，在数据管线

```
显存  peak 3533 MiB 稳定不涨      GPU 利用率 3~11%   温度 57°C
CPU   单核跑满，总占用 7%         步速  3.0 s/it → 20.5 s/it（第 290 步起）
```

8GB 卡上跑 QLoRA，**显存不是瓶颈**（只用了 3.5GB），**单线程数据管线才是**。
后半程 GPU 在等数据，利用率掉到个位数。这是 50 分钟里约 1/3 时间被浪费的原因。

## §4 结果

**两组对照**，因为第一种评估方式本身有方法学问题：

- **A 组**：用 `generate_comments.py` 的 v2 长指令（含「三分之一带表情」等分布要求）
- **B 组**：用**训练时的格式**（短 system + 话题式 user，无任何分布要求）← **主口径**

> ⚠️ v2 长指令对 LoRA 是**分布外输入**：LoRA 从没见过那种长指令，
> 而 v2 里「三分之一带表情」会被 LoRA 当成强指令去执行（底座没训过，反而不敏感）。
> 所以 **A 组不能用来说明训练效果**，只作为「提示词控不住分布」的旁证。

### §4.1 长度分布（主口径 B 组）

| 口径 | 模型 | n | 中位 | 均值 | <10字 | >80字 |
|---|---|---|---|---|---|---|
| 全池 | **真人** | 1053 | **23.0** | **41.8** | **14.8%** | **11.3%** |
| 全池 | 底座 | 28 | **132.0** | 142.5 | 0.0% | **96.4%** |
| 全池 | **LoRA** | 28 | **29.0** | **37.7** | 3.6% | 7.1% |
| 等权 | 真人 | — | 24.7 | 43.8 | 14.8% | 11.4% |
| 等权 | 底座 | — | 146.9 | 142.5 | 0.0% | 96.4% |
| 等权 | LoRA | — | 34.6 | 37.7 | 3.6% | 7.1% |

**这是本轮最明确的改善。** 底座在同一 prompt 下写 132 字论述（96.4% 超 80 字），
LoRA 把中位压到 29、均值压到 37.7（真人 41.8），**长度分布从「完全不像」变成「接近」**。

剩下两个缺口：
- **<10 字占比 3.6%（真人 14.8%）**：真人会说「笑死就走」，模型几乎不写一句话
- **>80 字 7.1%（真人 11.3%）**：长尾略少，但方向对了

**逐视频压平检测**（防「所有话题写一个长度」）：

```
真人              min 17  max 36  跨度 19
底座(train格式)    min 124 max 183 跨度 59   ← 全都超长，无高低之分
LoRA(train格式)    min 17  max 55  跨度 38   ← 比真人还分散
```

LoRA 的跨度比 2.0× 真人——**没有压平**，甚至会按话题变长短。这条是过的。

### §4.2 表情率

| 模型 | 表情率 | 真人 36.1% |
|---|---|---|
| 底座(train) | 14.3% | 偏低 |
| **LoRA(train)** | **78.6%** | ❌ **严重超标 2.2 倍** |

**这是本轮最明确的失败。** 训练语料里真人 36% 带表情，LoRA 学成了「几乎每条都带」，
而且经常**堆一串**：

```
[doge]我就是那个大肥鱼[doge][doge]
[星星眼][微笑]我只敢说：这视频好可爱呀！！哈哈哈，是死我了吗？[doge]
```

推测原因：LoRA 学到的是「B 站评论有表情」这个特征，但没学到**频率**。
表情在训练集里是强特征，模型倾向于过度泛化（over-apply）。
A 组（v2 提示词）下是 67.9%，B 组 78.6%——**换 prompt 没救，是权重里学进去的。**

### §4.3 骨架重复率（防套话塌缩）

| 口径 | 模型 | 骨架重复率 | 短评去重率(len<30) | 最常见骨架 |
|---|---|---|---|---|
| 全池 | **真人** | **3.2%** | **99.1%** | 「肥鱼来肥鱼来」×6 |
| 全池 | 底座(train) | **25.0%** | nan（无短评） | — |
| 全池 | **LoRA(train)** | **0.0%** | 100.0% | 无重复 |

判据是 **≤5%**。LoRA **0.0%**，过。底座 25.0%，远超标——底座在少数模板里打转。

> 为什么底座重复率高：它每条都写成同一套「这视频太X了 / 这游戏真的太X了」结构，
> 见 §4.5。

### §4.4 loss 对照（防「训了等于没训」）

同一 holdout（20 条）、同一 max_len、**loss 只算 assistant 段**（不含 system/user）：

| 模型 | loss | perplexity | p_target |
|---|---|---|---|
| 底座 | 11.4202 | 91,147 | 0.0011% |
| **LoRA** | **4.5727** | **96.8** | **1.03%** |
| 差 | **−6.85** | | ×940 |

**这一项决定了「不是没学到」。** 开放式生成的 SFT loss 绝对值看着高（4.5）是正常的——
一个视频下几百条评论都算对，模型没法预测用户具体写了哪句。
关键是**底座 vs LoRA 的差距**：6.85 个点，底座给人话的概率是 0.0011%，LoRA 是 1%。

### §4.5 「分布对上 ≠ 写着像人」：内容是空心的

底座（v2 组）的输出，**换到任何视频都成立**：

```
整活视频   → 这视频太爽了，笑死了
游戏视频   → 这游戏真的太懂我了
游戏视频   → 这游戏太真实了
美食视频   → 这道菜真的下饭啊
科技视频   → 这视频太真实了
```

它的长度和表情率能「凑」到接近真人（§4.1 A 组中位 12 vs 23、表情 36.4% vs 36.1%），
**但内容是泛泛感叹，没有一句和具体视频绑定**。这是 Goodhart's law 的教科书案例：
指标满足了，目的没满足。

LoRA 也没有真正解决这个问题，它学到的是**语域**而不是**内容**：

```
美食区 → 我的理解是，中国人认为菜要吃的有味，而且必须配主食…[doge]   ← 像人说话，但在讲常识
科技区 → 说实话真的太羡慕你们了，我最近都还没把这游戏弄好[doge]      ← 说错了主题（不是游戏）
整活区 → [doge]我就是那个大肥鱼[doge][doge]                        ← 这条反而沾题（标题有「大肥鱼」）
```

**所以：分布指标全部改善，但「说的是不是这个视频的事」没改善。**
这一条无法用分布指标衡量，只能读——这也是本报告最该被记住的结论。

## §5 A 组（v2 长指令）对照：证明「提示词路线」不可靠

| 模型 | n | 中位 | <10字 | >80字 | 表情 | 骨架重复 |
|---|---|---|---|---|---|---|
| 真人 | 1053 | 23.0 | 14.8% | 11.3% | 36.1% | 3.2% |
| 底座 | 140 | 12.0 | 43.6% | 0.7% | 36.4% | 21.4% |
| LoRA | 140 | 22.0 | 8.6% | 1.4% | **67.9%** | 0.7% |

同一批模型，只换 prompt：

- 底座：中位 12（B 组 132）→ **差 11 倍**，说明底座对 prompt 极其敏感、不可控
- LoRA：中位 22（B 组 29）、表情 67.9%（B 组 78.6%）

**结论**：靠写更长的 prompt 去调分布，会让结果在「太短」和「太长」之间乱跳，
且表情率反而更差。**提示词路线控不住分布**，这和 A 组的初衷一致。

## §6 已知局限（诚实列）

1. **B 组样本小**：n=4/视频 × 7 = **28 条/模型**（A 组是 140 条）。
   原因是训练格式下底座每条写 130~180 字，生成极慢（~4.3 tok/s，CPU 瓶颈），
   20 分钟窗口内跑不完 n=20。**B 组的分布指标抖动会比 A 组大。**
2. **训练集与评估集同源**：都是那 7 个视频的评论区。模型可能只是记住了这些评论区的话术，
   不代表在别的视频下也能写好。**这是最大的局限，没有留出视频做交叉验证。**
3. **holdout 只有 20 条**，且同源，不能当泛化证据。
4. **表情率 78.6% 的确切成因未做消融**。推测是训练集表情是强特征导致过度泛化，
   但**没有跑「去掉表情样本重训」这个对照**来证实。
5. **任务相关性只能靠读**，没有可用指标。试过「标题实词命中率」，真人侧只有 2%
   （真人自己也不复述标题），该指标无效，已放弃。
6. **P(AI) 只算了模型侧**（底座 0.3759 / LoRA 0.2972），**没算真人侧**做对照，
   所以 P(AI) 这一列无法解释。另外 263 条真人评论参与过该分类器训练，本身也偏乐观。
7. **没做温度扫描 / lr 扫描 / r 扫描**，所有结论绑定在这组超参上（r=16, lr=2e-4, 3 epoch, temp=1.25）。
8. **4B 没跑**（时间不够，未验证 8GB 上能否跑 4bit QLoRA）。
9. **35% 的通用样本（732 条 `generic`，user 是「说一句你此刻想说的话」）未做消融**。
   它可能教模型「不用管话题」，和 §4.5 的「内容空心」方向一致，但未验证。

## §7 如果继续，下一步该做什么（按性价比排序）

1. **去掉 732 条 generic 重训**（只改数据，参数不变）→ 验证「通用样本是否导致不看话题」
2. **表情降采样**或加「不要每条都带表情」的样本 → 压 78.6% → 36%
3. **按视频留出交叉验证**（train 6 个视频 / test 1 个）→ 验证是真泛化还是记住了话术
4. **补 <10 字样本** → 把 3.6% 拉到 14.8%
5. 以上都做完再考虑 4B
